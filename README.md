# 语聊房跨云双活架构设计方案

## 第1章 项目概述与目标

### 1.1 项目背景

随着语聊房业务规模扩大，单云部署面临以下挑战：
- **单点故障风险**：单云故障导致全站不可用
- **地域覆盖不足**：单地域无法满足全国用户低延迟需求
- **容量瓶颈**：单云资源上限限制业务增长
- **成本优化**：多云竞价资源降低成本

### 1.2 设计目标

| 目标 | 指标 | 说明 |
|------|------|------|
| 高可用 | RTO < 30秒 | 单云故障时30秒内完成切换 |
| 就近接入 | 延迟 < 100ms | 用户连接到最近的云节点 |
| 数据一致 | 零丢失 | 用户余额等关键数据不丢失 |
| 用户无感知 | 自动恢复 | 故障时用户自动重连，无需手动操作 |

### 1.3 核心概念定义

#### 1.3.1 房间归属云
每个房间创建时被分配到特定云区域（阿里云或腾讯云），房间的所有实时通信都在该云完成。

```
房间12345创建于腾讯云
  ├── WebSocket连接：腾讯云
  ├── RTC语音流：腾讯云TRTC
  └── 房间状态：腾讯云Redis

用户A（北京）和用户B（深圳）都进入房间12345
  └── 两人都连接到腾讯云（不管用户在哪）
```

#### 1.3.2 用户连接
用户本身没有"归属云"，用户根据所进入的房间位置，连接到对应的云区域。

```
用户A（北京）
  ├── 进入房间12345（腾讯云）→ 连接腾讯云
  ├── 进入房间67890（阿里云）→ 连接阿里云
  └── 同时进入多个房间？→ 不允许，同时只能在一个房间
```

#### 1.3.3 跨云与单云
- **单云内**：房间的所有用户都在同一朵云，消息直接广播
- **跨云**：只有房间元数据、用户数据需要同步，房间实时状态不跨云

### 1.4 设计原则

1. **房间自治**：每个房间完全独立，不依赖其他云
2. **用户无状态**：用户可以随时切换到任意云的房间
3. **数据分层**：不同数据采用不同同步策略
4. **故障隔离**：单云故障不影响其他云的房间
5. **渐进迁移**：支持从单云平滑迁移到双活

### 1.5 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 消息队列 | RocketMQ | 金融级可靠、顺序消息、事务消息 |
| 数据库 | MySQL + DTS | 阿里云RDS主库 + 腾讯云只读从库 |
| 缓存 | Redis | 阿里云主集群 + 腾讯云从集群 |
| RTC | 多云接入 | 阿里云RTC + 腾讯云TRTC |
| WebSocket | Workerman | 多进程、高并发、PHP生态 |

#### 1.5.1 为什么选RocketMQ？

| 特性 | RocketMQ | Kafka | RabbitMQ | 语聊房需求 |
|------|----------|-------|----------|-----------|
| 消息可靠性 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ | **必须5星** |
| 顺序消息 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐ | **必须5星** |
| 事务消息 | ⭐⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐ | **必须5星** |
| 延迟消息 | ⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐ | 定时任务需要 |
| 消息回溯 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | 故障排查需要 |

**核心原因**：
- 礼物交易不能丢消息 → 同步刷盘 + 主从复制
- 麦位状态必须有序 → 分区顺序消息
- 跨云扣款需要事务 → 事务消息

#### 1.5.2 为什么WebSocket和RTC分离？

| 维度 | WebSocket (IM) | RTC (语音) |
|------|---------------|-----------|
| 协议 | TCP | UDP为主 |
| 传输内容 | 小数据包（KB级） | 音频流（连续大数据） |
| 延迟要求 | < 500ms | < 200ms |
| 丢包处理 | 重传保证可靠 | 容忍丢包，追求实时 |

**根本原因**：TCP和UDP的本质差异
- WebSocket基于TCP：可靠传输，适合文字消息
- RTC基于UDP：低延迟传输，适合实时语音

#### 2.1.4 关键设计说明

| 设计要点 | 说明 | 优势 |
|---------|------|------|
| **房间云属性** | 房间创建时分配到特定云（阿里云/腾讯云） | 房间内数据天然一致，无需跨云同步 |
| **用户无云属性** | 用户可进入任意云的房间 | 灵活选择，负载自然均衡 |
| **统一房间列表** | API网关聚合两朵云的房间列表 | 用户无感知，体验一致 |
| **动态路由** | 根据房间位置路由到对应云 | 确保同房间用户同云 |
| **数据分层同步** | 元数据跨云同步，实时状态不跨云 | 平衡一致性和性能 |

### 2.2 核心组件职责

#### 2.2.1 全局调度中心

```
职责：
  1. 房间分配：创建房间时选择最优云区域
  2. 路由查询：提供房间所在云区域的查询服务
  3. 负载均衡：根据各云负载动态调整流量

部署方案（推荐方案B）：

方案A：独立部署（成本高）
  - 单独部署调度中心集群
  - 阿里云和腾讯云都访问独立的调度中心
  - 问题：调度中心成为新的单点

方案B：双云部署（推荐）
  - 阿里云部署调度中心主节点
  - 腾讯云部署调度中心从节点
  - 数据通过MySQL同步
  - 两朵云的调度中心数据一致

方案C：无调度中心（最简单）
  - 创建房间时随机/轮询选择云区域
  - 房间路由信息直接写MySQL
  - 查询时读MySQL获取房间位置
  - 适合初期，不需要独立调度服务
```

#### 2.2.2 数据同步层

```
职责：
  1. MySQL主从同步：阿里云RDS → 腾讯云RDS（DTS）
  2. Redis跨云同步：阿里云Redis → 腾讯云Redis（MQ）
  3. 消息队列桥接：阿里云RocketMQ ↔ 腾讯云CMQ

注意：
  - 只同步"需要全局一致"的数据
  - 房间实时状态不跨云同步
```

#### 2.2.3 WebSocket服务集群

```
职责：
  1. 维护用户连接（谁在线）
  2. 维护房间频道（谁在哪个房间）
  3. 转发文字/图片/礼物消息
  4. 处理麦位控制信令

特点：
  - 每朵云独立部署
  - 不跨云通信
  - 房间的所有用户都在同一朵云
```

#### 2.2.4 RTC服务

```
职责：
  1. 音频流转发（谁说话就转发给谁）
  2. 音频混音处理
  3. 3A处理（降噪、回声消除、自动增益）

特点：
  - 使用云厂商RTC服务（阿里云RTC/腾讯云TRTC）
  - 不需要自研媒体服务器
  - 按房间所在云选择对应RTC服务
```

#### 2.3.3 为什么这样设计？

```
✅ 正确设计：
```

**关键理解：**
- 用户**先看到房间列表**（包含所有云的房间）
- 用户**选择房间**后，根据房间位置**连接到对应云**

| 场景 | 用户位置 | 选择房间 | 连接到 |
|------|---------|---------|--------|

| 用户2在北京 | 北京 | 房间B（阿里云） | 阿里云 |
| 用户3在深圳 | 深圳 | 房间A（腾讯云） | 腾讯云 |
| 用户4在深圳 | 深圳 | 房间B（阿里云） | 阿里云 |

#### 2.4.3 架构优势

```
✅ 房间内数据一致性
  房间A在腾讯云 ──► 所有在房间A的用户都连接腾讯云
              ──► WebSocket消息直接广播（不跨云）
              ──► RTC语音流直接转发（不跨云）
              ──► 数据完全一致，无延迟

✅ 负载均衡
  房间分布在两朵云 ──► 用户自然分流到两朵云
                 ──► 单云压力不会过大

✅ 故障隔离
  腾讯云故障 ──► 只有腾讯云房间受影响
           ──► 阿里云房间正常运行
           ──► 用户可以切换到阿里云房间
```

**核心原则**：
- 房间**有云属性**（创建时分配到特定云）
- 用户**无云属性**（可以进入任意云的房间）
- 同房间**同云**（保证数据一致性）

### 2.5 核心设计约束

1. **房间自治约束**
   - 一个房间的所有用户必须在同一朵云
   - 房间内消息不跨云转发

2. **数据分层约束**
   - 房间元数据跨云同步（最终一致）
   - 房间实时状态不跨云同步
   - 用户数据跨云同步（强一致）

3. **故障隔离约束**
   - 单云故障只影响该云的房间
   - 其他云的房间正常运行
   - 用户可切换到其他房间

4. **性能约束**
   - 房间创建延迟 < 100ms
   - 消息转发延迟 < 50ms
   - 路由查询延迟 < 20ms

#### 3.2.2 数据库路由策略

```php
/**
 * 数据库路由器
 * 
 * 根据操作类型和数据表，自动选择数据库连接
 */
class DatabaseRouter {
    
    // 关键表定义（写操作必须走主库）
    private $criticalTables = [
        'user_balance',      // 用户余额
        'user_earnings',     // 用户收益
        'gift_records',      // 礼物记录
        'recharge_records',  // 充值记录
    ];
    
    // 当前云区域
    private $currentRegion;
    
    public function __construct($region) {
        $this->currentRegion = $region; // 'aliyun' or 'tencent'
    }
    
    /**
     * 获取数据库连接
     * 
     * @param string $operation 'read' or 'write'
     * @param string $table 表名
     * @return Connection
     */
    public function getConnection($operation, $table) {
        // 写操作：必须走阿里云主库
        if ($operation === 'write') {
            return $this->connectAliyunMaster();
        }
        
        // 读操作：关键表强制读主库（避免延迟）
        if (in_array($table, $this->criticalTables)) {
            // 检查是否需要强一致读
            if ($this->requiresStrongConsistency($table)) {
                return $this->connectAliyunMaster();
            }
        }
        
        // 普通读操作：走本地从库
        if ($this->currentRegion === 'aliyun') {
            return $this->connectAliyunMaster(); // 阿里云读主库
        } else {
            return $this->connectTencentSlave(); // 腾讯云读从库
        }
    }
    
    /**
     * 判断是否需要强一致读
     * 
     * 场景：刚写完立即读（如送礼物后查余额）
     */
    private function requiresStrongConsistency($table) {
        // 检查最近是否对该表有写操作
        $lastWrite = Redis::get("db:last_write:{$table}");
        if ($lastWrite && (time() - $lastWrite) < 5) {
            // 5秒内有写操作，强制读主库
            return true;
        }
        return false;
    }
    
    /**
     * 标记写操作
     */
    public function markWrite($table) {
        Redis::setex("db:last_write:{$table}", 5, time());
    }
}
```

#### 3.2.3 送礼物场景的数据一致性

```php
/**
 * 送礼物服务
 * 
 * 核心挑战：余额查询和扣减必须一致
 */
class GiftService {
    
    private $dbRouter;
    
    public function __construct() {
        $this->dbRouter = new DatabaseRouter(getCurrentRegion());
    }
    
    /**
     * 送礼物
     */
    public function sendGift($fromUserId, $toUserId, $giftId) {
        // 1. 获取礼物价格
        $giftPrice = $this->getGiftPrice($giftId);
        
        // 2. 查询余额（强制读主库，确保一致）
        $conn = $this->dbRouter->getConnection('read', 'user_balance');
        $balance = $conn->table('user_balance')
            ->where('user_id', $fromUserId)
            ->value('balance');
        
        // 3. 检查余额
        if ($balance < $giftPrice) {
            return ['error' => '余额不足'];
        }
        
        // 4. 扣减余额（写主库）
        $writeConn = $this->dbRouter->getConnection('write', 'user_balance');
        $writeConn->transaction(function() use ($fromUserId, $toUserId, $giftId, $giftPrice) {
            // 扣减赠送方余额
            $writeConn->table('user_balance')
                ->where('user_id', $fromUserId)
                ->decrement('balance', $giftPrice);
            
            // 标记写操作（影响读路由）
            $this->dbRouter->markWrite('user_balance');
            
            // 增加接收方收益
            $writeConn->table('user_earnings')
                ->where('user_id', $toUserId)
                ->increment('earnings', $giftPrice * 0.7);
            
            // 记录礼物日志
            $writeConn->table('gift_records')->insert([
                'from_user' => $fromUserId,
                'to_user' => $toUserId,
                'gift_id' => $giftId,
                'price' => $giftPrice,
                'created_at' => now(),
            ]);
        });
        
        return ['success' => true, 'new_balance' => $balance - $giftPrice];
    }
}
```

```php
/**
 * 主从延迟监控服务
 */
class ReplicationLagMonitor {
    
    /**
     * 检查主从延迟
     */
    public function checkLag() {
        // 获取主库Binlog位置
        $masterStatus = DB::connection('aliyun')->select('SHOW MASTER STATUS');
        $masterFile = $masterStatus[0]->File;
        $masterPos = $masterStatus[0]->Position;
        
        // 获取从库执行位置
        $slaveStatus = DB::connection('tencent')->select('SHOW SLAVE STATUS');
        $slaveFile = $slaveStatus[0]->Master_Log_File;
        $slavePos = $slaveStatus[0]->Read_Master_Log_Pos;
        
        // 计算延迟
        if ($masterFile === $slaveFile) {
            $lagBytes = $masterPos - $slavePos;
            $lagSeconds = $slaveStatus[0]->Seconds_Behind_Master;
        } else {
            $lagSeconds = PHP_INT_MAX; // 文件不同，延迟极大
        }
        
        // 记录监控
        Metrics::gauge('mysql_replication_lag_seconds', $lagSeconds);
        
        // 告警处理
        if ($lagSeconds > 1) {
            Alert::warning("MySQL主从延迟: {$lagSeconds}秒");
        }
        
        if ($lagSeconds > 5) {
            // 延迟过大，触发降级：所有读操作走主库
            Redis::setex('db:force_master_read', 60, true);
            Alert::critical("MySQL延迟过大，已强制读主库");
        }
        
        return $lagSeconds;
    }
}
```

```php
/**
 * Redis双写服务
 * 
 * 写操作时同时写入阿里云和腾讯云
 */
class RedisDualWriteService {
    
    private $aliyunRedis;
    private $tencentRedis;
    private $mqProducer;
    
    /**
     * 双写Set操作
     */
    public function set($key, $value, $ttl = null) {
        // 1. 写入阿里云（主）
        $this->aliyunRedis->set($key, $value, $ttl);
        
        // 2. 异步同步到腾讯云
        $this->asyncSyncToTencent('set', [
            'key' => $key,
            'value' => $value,
            'ttl' => $ttl,
        ]);
    }
    
    /**
     * 双写Hash操作
     */
    public function hSet($key, $field, $value) {
        // 写入阿里云
        $this->aliyunRedis->hSet($key, $field, $value);
        
        // 异步同步
        $this->asyncSyncToTencent('hSet', [
            'key' => $key,
            'field' => $field,
            'value' => $value,
        ]);
    }
    
    /**
     * 异步同步到腾讯云
     */
    private function asyncSyncToTencent($operation, $data) {
        $message = [
            'op' => $operation,
            'data' => $data,
            'timestamp' => time(),
            'source' => 'aliyun',
        ];
        
        // 发送到MQ，腾讯云消费
        $this->mqProducer->send('redis.sync.tencent', json_encode($message));
    }
}

/**
 * 腾讯云Redis同步消费者
 */
class TencentRedisSyncConsumer {
    
    private $tencentRedis;
    
    public function consume($message) {
        $msg = json_decode($message, true);
        $op = $msg['op'];
        $data = $msg['data'];
        
        switch ($op) {
            case 'set':
                $this->tencentRedis->set($data['key'], $data['value'], $data['ttl']);
                break;
            case 'hSet':
                $this->tencentRedis->hSet($data['key'], $data['field'], $data['value']);
                break;
            case 'del':
                $this->tencentRedis->del($data['key']);
                break;
            // ... 其他操作
        }
    }
}
```

```php
/**
 * 缓存一致性服务
 * 
 * 处理缓存更新时的数据一致性
 */
class CacheConsistencyService {
    
    /**
     * 更新用户资料（先更新DB，再更新缓存）
     */
    public function updateUserProfile($userId, $data) {
        // 1. 更新数据库（主库）
        DB::table('users')->where('id', $userId)->update($data);
        
        // 2. 删除缓存（而不是更新，避免并发问题）
        $this->redisDualWrite->del("user:{$userId}:profile");
        
        // 3. 下次读取时从DB加载到缓存
    }
    
    /**
     * 读取用户资料（带缓存加载）
     */
    public function getUserProfile($userId) {
        $cacheKey = "user:{$userId}:profile";
        
        // 1. 读本地缓存
        $cached = $this->localRedis->get($cacheKey);
        if ($cached) {
            return json_decode($cached, true);
        }
        
        // 2. 缓存未命中，读数据库
        $profile = DB::table('users')->where('id', $userId)->first();
        
        // 3. 写入缓存（双写）
        if ($profile) {
            $this->redisDualWrite->set($cacheKey, json_encode($profile), 3600);
        }
        
        return $profile;
    }
}
```

```
  ✅ 用户余额/收益（强一致）
  ✅ 房间元数据（名称、封面、配置）
  ✅ 房间路由信息（房间在哪朵云）
  ✅ 用户关系（关注/粉丝）
  
这些数据：
  - MySQL主从复制同步
  - Redis双写同步
  - 故障时从其他云可读
```

### 3.5 数据迁移方案（已有数据）

```
阶段1：全量迁移
  - DTS全量迁移历史数据
  - 迁移期间业务只读
  - 预计停机2小时

阶段2：增量同步
  - Binlog增量同步
  - 数据追平后切换

阶段3：验证
  - 数据一致性校验
  - 业务功能验证
```
